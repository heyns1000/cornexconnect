## 3. REPOSITORY ACCESS AND MANAGEMENT

**3.1 Access Control**

The Recipient undertakes to:

3.1.1 Maintain strict access controls over all Repository Access Credentials and ensure they are shared only with authorized personnel on a need-to-know basis;

3.1.2 Never share Repository Access Credentials via unencrypted email, instant messaging, or unsecured channels;

3.1.3 Immediately revoke access credentials upon termination of employment or engagement of any personnel with Repository access;

3.1.4 Use unique, complex passwords and multi-factor authentication (MFA) for all Repository access where available;

3.1.5 Immediately notify the Disclosing Party of any unauthorized access or suspected compromise of Repository Access Credentials.

**3.2 Repository Integrity**

The Recipient irrevocably agrees to:

3.2.1 Maintain the integrity and security of the Repository and prevent unauthorized modifications to any files or commits;

3.2.2 Not delete, archive, or modify repository history except as expressly authorized by the Disclosing Party in writing;

3.2.3 Not fork, clone, or create copies of the Repository without prior written consent of the Disclosing Party;

3.2.4 Maintain detailed audit logs of all access to the Repository and provide these logs to the Disclosing Party upon request;

3.2.5 Implement branch protection rules to prevent direct commits to main/production branches;

3.2.6 Require code review and approval before merging any changes to protected branches.

**3.3 Repository Monitoring**

3.3.1 The Recipient acknowledges that the Disclosing Party may monitor all Repository activity, including access logs, commits, pulls, and push operations;

3.3.2 The Recipient consents to the collection and analysis of this data for security, audit, and compliance purposes;

3.3.3 The Recipient shall cooperate fully with any security audits or investigations conducted by the Disclosing Party.

## 4. SOURCE CODE PROTECTION

**4.1 Confidentiality of Source Code**

4.1.1 The Recipient acknowledges that the Source Code contains valuable trade secrets and proprietary information of the Disclosing Party;

4.1.2 The Recipient shall not disclose, publish, or distribute the Source Code or any substantial portions thereof to any third party without explicit written consent from the Disclosing Party;

4.1.3 The Recipient shall ensure that all employees, contractors, and consultants with access to the Source Code sign appropriate confidentiality and non-disclosure agreements containing terms substantially similar to this Addendum;

4.1.4 The Recipient shall maintain the Source Code in secure, encrypted storage and implement encryption for data in transit.

**4.2 Prohibited Activities**

The Recipient shall not, without prior written consent of the Disclosing Party:

4.2.1 Reverse engineer, decompile, disassemble, or attempt to derive the underlying algorithms or methodologies from the Source Code;

4.2.2 Remove, obscure, or alter any copyright notices, proprietary labels, or attributions in the Source Code;

4.2.3 Use the Source Code to develop competing products or services;

4.2.4 Extract or reuse any portions of the Source Code in other projects without explicit authorization;

4.2.5 Publish benchmarks, performance comparisons, or other analyses of the Software without prior written approval;

4.2.6 Use the Source Code for any purpose other than the Permitted Purpose.

**4.3 Secure Development Practices**

The Recipient agrees to implement and maintain:

4.3.1 Secure code repositories with encryption at rest and in transit;

4.3.2 Regular security testing including static code analysis, dynamic testing, and dependency scanning;

4.3.3 Secure development lifecycle practices including code review processes;

4.3.4 Incident response procedures for security breaches involving the Source Code;

4.3.5 Separation of production credentials from Source Code repositories;

4.3.6 No hardcoding of secrets, API keys, passwords, or other sensitive credentials in Source Code.

## 7. AUTHENTICATION AND CREDENTIALS MANAGEMENT

**7.1 Credential Storage**

The Recipient shall:

7.1.1 Store all Repository Access Credentials in a secure password manager or secrets vault;

7.1.2 Use encrypted, role-based access to secrets and API keys;

7.1.3 Implement automatic credential rotation on a regular schedule;

7.1.4 Never commit credentials or secrets to any Repository;

7.1.5 Use environment variables or configuration management tools for credential injection.

**7.2 Credential Sharing**

7.2.1 Repository Access Credentials shall never be shared via email, chat, or other insecure channels;

7.2.2 Credentials shall be shared only through secure methods such as encrypted password managers;

7.2.3 Access shall be revoked immediately upon request or when no longer needed;

7.2.4 A minimum of two authorized individuals from the Disclosing Party must approve any credential sharing.

**7.3 Incident Response**

Upon discovery of any compromise or unauthorized access involving Repository credentials:

7.3.1 The Recipient shall immediately notify the Disclosing Party;

7.3.2 The Recipient shall immediately revoke compromised credentials;

7.3.3 The Recipient shall provide a detailed incident report including timeline and scope of exposure;

7.3.4 The Recipient shall cooperate fully with any investigation.

**8.1 Personal Data**

8.1.1 The Recipient shall not commit or store any personal data, personally identifiable information (PII), or sensitive personal information in any Repository;

- Remove the data from Repository history
- Rotate any exposed credentials
- Investigate how the exposure occurred

11.1.2 Encrypt all backups using strong encryption algorithms;

## 14. SECURITY BREACH NOTIFICATION

**14.1 Immediate Notification**

Upon discovery of any security breach, unauthorized access, or compromise of Confidential Software Assets, the Recipient shall:

14.1.1 Notify the Disclosing Party immediately (within 24 hours);

14.1.2 Provide initial details of the breach, scope, and potential impact;

14.1.3 Preserve all evidence and logs related to the breach;

14.1.4 Cease all potentially affected systems if necessary to prevent further compromise.

**14.2 Breach Investigation and Reporting**

14.2.1 The Recipient shall conduct a thorough investigation of the breach;

14.2.2 Within 5 business days, the Recipient shall provide a detailed incident report including:
- Timeline of discovery and initial notification
- Nature and scope of the breach
- Data or systems affected
- Root cause analysis
- Remediation steps taken
- Preventive measures implemented
- Third parties affected

**14.3 Regulatory Reporting**

14.3.1 The Recipient shall cooperate with the Disclosing Party in any required regulatory notifications or disclosures;

14.3.2 The Recipient shall not make public disclosures about the breach without prior written consent from the Disclosing Party.
